About this map

This map shows the trails, points of interest, and scenic overlooks and their viewsheds in High Cliff State Park. This map is intended for people planning to visit or currently visiting the park. This map will help with trip planning and navigation within the park. There is no existing interactive web map for this park and the trails and it is important to provide this service to park visitors as it is easier to navigate and use than a static map.


How to use this map

  • Search for a trail by name in the search bar.
  • Use the layer control to toggle layers on and off.
  • Hover over a trail to highlight it.
  • Click the home button on the map to return to the original view.
  • Click the info button on the map for addional map informtion.
  • Click the location button on the map to see real-time location for in-park navigation.
  • Click on overlook button to enable a polygon showing the areas visible from that spot.

Methodology

  • The static park map was brought into ArcGIS Pro and georeferenced and points of interest such as bathrooms, scenic overlooks, and parking lots were manually digitized.
  • The trail lines were dissolved, so that each trail was represented by only one line and all fields except name, mileage, and usage were deleted.
  • The slope data was derived by using the DEM and the trail line data. The trail lines were split into 5 foot segments using the "Generate Points Along Lines" and "Split Line at Points" tools in ArcGIS Pro. The DEM data was then added to each segment using the "Add Surface Information" tool using the average slope.
  • The viewsheds were calculated using the scenic overlook points and the DEM. First, the "Observer Points" tool was used to determine the areas visibile from each overlook, then the "Minimum Bounding Geometry" tool was used to encompass the pixels visible to produce a single polygon of visible area for each viewpoint.
  • Feature classes were exported from ArcGIS Pro using the "Feature to JSON" tool, checking the boxes to Output to GeoJSON and to reproject to WGS84. Within the coding software, a variable name was added to the data and the file was changed from .geojson to .js and the data was then added to the map.

Design Justifications

  • The legends for layers are automatically hidden when the layer is turned off and not visible on the map. This ensures that users are not overwhelmed with extraneous information in the side panel with legends for layers they do not wish to view at that given time. The reduction of visible clutter and information on the page makes the map seem less intimidating and more manageable for first-time users.
  • The color scheme for the slope segments along the trail line follows what users would intuitively understand: green is easier (flatter) and red is harder (steeper). This means that users can gain an general understanding of the slope of the park and the trails without needing to reference the legend. They can identify flatter and steeper areas quickly to best fit their needs for their visit.
  • When the buttons to enable the viewsheds are hovered over, the overlook that corresponds with that button becomes highlighted with a soft yellow glow behind the icon. This is so that users can easily identify which overlook they are enabling the viewshed for, rather than assuming that all users know the name of all of the overlooks in the park.
  • The viewsheds for the overlooks are represented as simplified polygons, rather than the raster pixels that were the true output of the ArcGIS Pro tool that produced the viewsheds. The two main reasons behind this design choice are: file size and user interpretation. First, the DEM that was used to create the viewsheds for the four overlooks had 2-foot accuracy, meaning the resolution of the DEM and outputs that use it is very high and detailed and with that, files sizes become very large. Large file sizes can become problematic when using a free platform like GitHub to store files due to the limited storage space that comes with free accounts. Second, users who do not have technical background in GIS analysis may not be able to easily interpret the raster output of the Observer Points tool in ArcGIS. The visible pixels can be sporadic and scattered and not have much meaning to the average user. Instead, having a polygon that encompasses the area of the visibile pixels is much easier to interpret, as the area within the polygon should be visible from that overlook. An additional benefit of using a polygon instead of the pixels is that the file size is significantly smaller and more manageable by the free storage on GitHub. Large file sizes can also slow down the performance of the page, so limiting the size of the files used can reduce loading speed and increase performance of the page overall.
  • The AlmostOver Leaflet plugin was incorporated into the trail lines for this map. Before this plugin was used, the interaction with the trail lines, such as clicking or hovering, required precise mouse placement directly over the lines. After the addition of this plugin, a buffer region was added around the lines for interaction to occur so, the highlight effect that appeared while hovering over the lines, now appears when the mouse is almost over the line, within the buffer region rather than requiring the user to be precisely over the line feature.

Project Summary and Credits

  • Strengths:
    - The legends that automatically hide when the layer is not visible on the map reduces visual clutter and enables users to focus on the information they wish to see
    - The ability to get the real-time location of the user will be useful for people who are actively in the park and navigating
    - Overall, the webpage works quickly and reacts fast, even with the size of data integrated
    - Buffer around line features that allow interaction without precise mouse placement
  • Limitations:
    - Some of the main attractions such as the Cheif Red Bird Statue and Lime Kiln Ruins are not documented on this map
    - The viewshed polygons may be inaccurate due to:
    • Underestimation: The DEM was segmented and only sections that contained areas of the park were combined and used for analysis.
    • Overestimation: The polygons were created using the minimum bounding geometry to encompass the raster pixels and include areas between pixels that were technically not visibile according to the Observer Points tool in ArcGIS Pro.
  • Next steps:
    - Fine-tune the colors for the trail lines and viewshed polygons
    - Add more details to trail popups (e.g., estimated time to complete, difficulty, or highlights of the trail)
    - Create toggle for colorblind-friendly mode: changes color scheme of slope to be more easily distinguished by those who are colorblind.
